# DNDL 接入与信息架构重设计

> 记录本次品牌重设计（DNDL v1.0 / 实现 1.1.0）的接入方式、信息架构推导与取舍。
> 产品设计推导见 `design-derivation.md`，本文不修改其中任何产品原则。

## 一、为什么重做

重做前的界面存在三类可验证的问题：

1. **配色与文档互相矛盾**：`AGENTS.md` / `CLAUDE.md` 写的是 terracotta 暖调
   （`#C96442` / `#FDF9F4` / `#2C1A0E`），`tailwind.config.ts` 里还留着
   `espresso/cream/terracotta/sage` 四组旧色（全站 0 处使用），
   而 `globals.css` 实际已换成蓝灰调（`#4659B8` / `#F2F5F7`），
   焦点环又仍是旧的 `#C96442`。三份来源互不一致，无法判断哪个是品牌。
2. **样式静默失效**：Tailwind v3 无法给 `var(--x)` 颜色应用透明度修饰符。
   全站 224 处 `bg-primary/10`、`text-muted-foreground/40`、`border-border/30`
   等类**从未生成过 CSS**（在旧的生产构建产物中同样搜不到这些选择器）。
   其中 `text-muted-foreground/40` 一类直接把次要文字压到远低于 4.5:1。
3. **表达方式与产品主张不符**：产品主张「把每条路真实的样子摆出来」，
   界面却是等分的白色圆角卡片网格 + emoji 图标，信息密度低，
   真实数据（181 个专业起薪、48 个城市成本、310 条资源）在首页完全不可见。

## 二、DNDL 接入方式

- 以确定版本引入：`public/vendor/dndl/{tokens.css, materials.css, motion.css, LICENSE, VERSION}`，
  来源仓库 `dreamnight16/dreamnight-design @ 3d0658e`，实现版本 1.1.0。
  文件逐字节与上游一致，不就地改动任何数值。
- 在 `src/app/layout.tsx` 通过 `<link>` 加载，保持三份文件的同级关系，
  不引用可变默认分支，不引入 CDN 或字体下载。
- `src/app/globals.css` 只做**语义映射**：把 shadcn 的 `--background/--primary/...`
  指向 `--dn-*`，并新增产品局部类 `.cc-*`。不重新定义任何品牌原始色。
- 需要浅色调（选中/悬停等小面积状态）时用 `.cc-tint-*`，
  由 `color-mix()` 从品牌 Token 派生，并内置不支持时的 Canvas 回退。

## 三、信息架构改动

产品原有的 8 个模块与 `?tab=` 取值全部保留、路由不变。改动在于**分组与入口层级**：

| 段 | 主题 | 模块 | 标识色 |
| --- | --- | --- | --- |
| 辅助 | 可选的摊开取舍 | `coach` 决策教练 | Teal |
| 一 | 看清自己 | `profile` 个人画像 | Cyan |
| 二 | 看清路 | `careers` 路径探索 · `explore` 数据对比 · `resources` 资源库 | Emerald |
| 三 | 做决定 | `sim` 路径模拟 · `journal` 决策日志 | Violet |
| 四 | 走下去 | `routes` 成就图鉴 | Amber |

- 四段推进直接来自产品自己的方法论（`design-derivation.md` 的 CIP CASVE 循环与
  「三层同心圆」不排优先级的结论）：先看清自己，再看清路，然后自己决定。
- 决策教练单独提出来而不是塞进某一段，因为它在产品定位里是**可选辅助**，
  不是流程的一环——这与「人主导规划」原则一致。
- 导航色只承担**分组识别**，不承担状态：阶段标题在 Ink 场上一律使用可读的
  中性色，色相只作为实色标记块出现；选中态才使用整块品牌实色场。
- 移动端底部只保留决策教练 / 个人画像 / 路径探索三个高频入口，
  其余 5 个模块按同样四段分组收进「更多」面板，全部入口仍可到达。

## 四、布局与表达

- 首页改为不对称 12 栏构图：左侧 7 栏是排版（`--dn-font-display` 300 字重的
  Display 级标题），右侧 5 栏是一块 Ink 实色场，直接展示真实的起薪分布
  （最高 5 / 最低 5 个专业）与数据来源、数据文件记录时间。
- 第二屏是「四段路」歧路板：`col-span` 按内容重要度分配 12 / 5+7 / 7+5，
  每段是一块品牌实色场，模块是场内的行式入口，字段之间用 1px Divider 分隔，
  不再使用等分卡片网格。
- 排版承担层级：色块上的正文一律 `--dn-text-on-color`，用字号/字重/间距区分
  主次，不用透明度压暗文字（压暗会掉到 3.8:1 以下）。
- 阴影只用于解释层级：Level 0/1 无阴影；Acrylic 仅用于覆盖层（移动端「更多」
  面板、抽屉、模态），且由 materials.css 提供不透明回退。
- 动效只解释状态：删除了循环脉冲、流光、骨架微光等持续运动，
  入场统一为 `.dn-rise` 一次性交错升入，不随数据刷新重播。

## 五、与既有设计意图的关系

没有改动 `design-derivation.md` 中的任何产品原则：

- 「AI 辅助，人主导规划」→ 决策教练在版式与文案上都是可选入口，且明说不给答案；
- 「数据可追溯」→ 首页直接列出数据来源与来源文件名，知识条目保留可信度标记；
- 「不做推荐、不默认某条路」→ 四段板里没有任何"推荐"话术，只列路和代价；
- 「信息优先」→ 首页展示的是真实静态数据，并明确标注是静态数据、不自动刷新。

唯一被替换的是**视觉语言**：terracotta 暖调 + 蓝灰调两套并存的旧状态，
统一为 DNDL 品牌色板与直角几何。这属于品牌基准，不属于产品原则。

## 六、已知边界

- 未做真实浏览器人工走查，只做了构建期与静态输出检查。
- 本仓库不声称整体通过 WCAG 认证；只核对了语义文字配对与主要实色场上的对比度。
- `src/data/catalog.ts` 中的 `ACHIEVEMENT_COUNT` / `CAREER_ENTRY_COUNT`
  是两个无法在构建期从源文件读取的常量，已注明对应源文件，修改源文件时需同步。
